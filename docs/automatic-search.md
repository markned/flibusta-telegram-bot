# Автоматический поиск по каталогу

Изменение от 2026-11-12. Реализуется в проекте `flibusta-codex-skills`, который обслуживает «Полку» на Oracle, а не в старом checkout `flibustabot`.

## Поведение

Одна строка проверяется как название и как автор. При совпадении обоих типов Telegram и web показывают две группы: «Есть автор с таким именем и книги с таким названием». Для естественного ввода известного имени проверяется также строго совпадающее название; биографии и упоминания имени не становятся заменой авторскому каталогу. Явные запросы «книги автора» сохраняют авторский режим.

Имя проверяется целиком с учётом порядка слов, регистра, е/ё и допустимого отсутствия отчества. Кандидаты извлекаются исходным запросом, фамилией и ограниченными дополнительными вариантами: максимум четыре author-запроса, по два параллельно. Фамилия больше не заменяется одной лишь короткой подстрокой. Для полностью латинского ввода добавляется один вариант русской транслитерации; раскладка остаётся отдельным вариантом. Оригинал и точные результаты имеют приоритет.

Единственное близкое имя из реальных ответов каталога автоматически разрешается в автора, и его книги выводятся с пометкой «Возможно, вы искали…». Известное/сохранённое имя само по себе не подтверждает наличие автора: перед выдачей нужны ответ каталога, actual author_id и проверенная авторская страница. При отсутствии подтверждения остаётся подсказка; при нескольких вариантах — выбор. Прямой power-user поиск автора сохраняет совместимость с явным подтверждением коррекции.

Книжная выдача проверяется по всему исходному запросу, включая издания. Для токенов автора в составе книжного совпадения повышен минимальный lexical score с 0.63 до 0.75: «Филина» больше не подтверждается словом «Галина». Более мягкое сравнение полного имени используется для получения кандидатов, а не как разрешение показывать книги произвольного человека. Сокращение запроса не меняет условие принятия результата.

## Время и постепенная выдача

Общий search deadline не больше 15 секунд, даже если старый production параметр равен 35. Книжный source вызов ограничен 5 секундами, другие — максимум 8; параллельные авторские пробы получают достаточно времени для реального источника вместо прежних 0.75 секунды на всю проверку автора.

Telegram получает промежуточные проверенные авторские/книжные результаты через request-local callback. Callback имеет собственный секундный бюджет, его ошибка не уничтожает результат поиска. Повторяющиеся публикации одних и тех же ID подавляются. При найденном авторе незавершённая книжная ветка получает короткий grace period для обнаружения совпадающего названия, затем отменяется; partial notice честно обозначает незавершённость дополнительных вариантов. Зависший источник не позволяет гарантировать полноту обеих групп.

## Почему не просто другая fuzzy-библиотека

Нужны отдельные retrieval, validation и presentation, а не один similarity score. [RapidFuzz token_set_ratio](https://rapidfuzz.github.io/RapidFuzz/Usage/fuzz.html) допускает максимальную оценку при совпадении подмножества слов — без полного query guard это повторит проблему. Существующее ограниченное сравнение используется для небольшого пула имён; новая зависимость не нужна. [SQLite FTS5](https://www.sqlite.org/fts5.html) применим к локальному корпусу, но не добавляет отсутствующие метаданные удалённого каталога. Полный индекс Flibusta и новые сервисы в этот релиз не включены.

## Проверки

- `TELEGRAM_BOT_TOKEN=123456:dummy make check`: 433 tests, lint, compile и skill checks; сеть/Telegram/SMTP в тестах подменены.
- Новая матрица: 79 случаев — 12 некурируемых авторов с перестановками, регистром, пробелами, удалениями и перестановками букв; негативные и неоднозначные случаи. Дополнительные tests проверяют конкретные регрессии, транслитерацию, прогресс, два типа результатов, известное имя как literal title, Telegram UI и отсутствие лишнего подтверждения.
- Golden routing: 67/67. Существующий benchmark: 90/90 top-5 на 30 synthetic книгах. Это не измерение recall настоящего каталога.
- Отдельная проверка staged кода на Oracle, без перезапуска бота, только публичные метаданные: Алла Сергеевна Филина, author_id `324933`, найдена за 1.47 s, книги `837772` и `841361` получены за 2.77 s; Оливер Беркман, author_id `281212`, найден за 1.90 s, книги за 3.71 s, включая `785139` («Четыре тысячи недель»). Это единичные live замеры, не p95 и не гарантия скорости.

Зависимости, SQLite schema, access control, reader concurrency и доставка не менялись. Недоступный источник остаётся отдельным состоянием, а не доказательством отсутствия книги. Всесторонний live recall без размеченного корпуса не заявляется.
