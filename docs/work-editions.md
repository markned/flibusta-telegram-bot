# Произведения, издания и полный каталог автора

Раньше список автора загружал первые 40 записей и показывал 5 страниц по 8 книг
как весь каталог. Теперь отдельный `author_works_page` выдаёт порции произведений,
реальное общее число и продолжение. Telegram загружает следующие 40 произведений
при переходе за уже полученный участок; веб загружает нужную страницу по 8.

Flibusta публикует названия и ID автора одним HTML-указателем без серверного
пейджера. Указатель читается один раз и кэшируется в существующем SQLite под
ключом `author_books:<id>:catalog-v3`. Это только метаданные, а не карточки или
файлы книг. Последующие страницы используют кэш. Старые записи кэша на 40 книг
сохраняются для совместимости, но не используются для полного каталога.

## Группировка

Общий `group_books` применяется в поиске, каталогах авторов, жанрах и подборках.
Одно произведение — одна строка; каждый исходный ID остаётся в списке изданий.
Учитываются известные пометки издания/перевода, подписи томов, книг и частей,
римские и арабские номера, а также явный «Первый вариант романа».

Идентичность требует совпадения названия произведения и автора. Без известного
автора разные ID не объединяются. Сборники, планы, заметки и комментарии не
превращаются в основной роман. Неопознанные смысловые подзаголовки остаются
отдельными; нечёткое или AI-сопоставление здесь не используется.

В авторском каталоге произведения сортируются по алфавиту; подборки сохраняют
относительный порядок рейтинга. Издания внутри произведения сортируются так,
что полные варианты идут перед отдельными томами, тома — по номеру (III = 3).
Разные издания одного тома остаются доступными, не теряя свои book_id.

## Открытие и выбор

Если есть вариант с названием произведения без признаков отдельного тома,
фрагмента, сокращения или чернового варианта, открывается его карточка. Если
такого варианта нет, сначала показывается выбор изданий/томов. Полнота оценивается
по подписи каталога, без скачивания и анализа текста книги.

Кнопка «Издания и тома» сохраняет полный выбор. При необходимости остальные
издания догружаются из указателя автора по настоящему author_id из карточки
Flibusta, с проверкой личности автора. Это позволяет открыть другие издания
также из поиска или популярной подборки, где изначально была только одна запись.
Каждая выбранная версия открывается по своему исходному ID; код скачивания и
отправки на читалки не изменён. Карточка сохраняет возврат на прежнюю страницу.

Telegram проверяет пользователя, чат, произведение и выбранный ID. Веб выдаёт
непрозрачные ссылки `/work/<token>`: они привязаны к пользователю, живут 30 минут
и не допускают открытия произвольного ID через выбор издания. Устаревшая ссылка
просит открыть выдачу заново. Веб не требует JavaScript или современного WebKit.

## Ресурсы и совместимость

- Один полный указатель автора загружается за раз; одинаковые запросы объединяются.
- HTML ограничен 2 MiB распакованных данных. Превышение или неузнаваемая разметка
  дают явную ошибку, а не ложное сообщение о конце каталога.
- Парсер проходит ссылки один раз и не пересканирует всю HTML-форму для каждой
  книги. Карточки изданий не запрашиваются заранее.
- Сохраняются общие HTTP-пулы, дедлайны, circuit breaker и stale-cache.
- Веб-хранилище ссылок: максимум 128 записей и 8192 ссылки на издания суммарно;
  ограничение действует также при догрузке вариантов.
- Telegram использует существующее ограниченное хранилище поисковых сессий.
- Схема SQLite, production-зависимости, reader concurrency и фоновые задачи не
  меняются. Топы сохраняют прежнюю трёхполевую форму записи для совместимости.
- Старый кэш SearchResult читается с пустыми дополнительными полями; новый кэш
  сохраняет ссылки на издания без рекурсивных структур.

## Проверка

Офлайн-тесты покрывают группировку, раздельность авторов/сборников/заметок,
сохранность ID, отсутствие ложного полного текста, номера томов, JSON roundtrip,
страницы после пятой, принадлежность сессий и возврат, лимиты веб-хранилища,
сжатый HTML, ограничение размера, ошибки источника и догрузку изданий по требованию.
Команды: `make check`, `make test-search`, `make test-kindle`,
`make search-quality`, `make search-benchmark`.

Benchmark проверяет точное название и автора конкретного издания внутри
видимого произведения: нужный том не считается найденным лишь потому, что
найден другой том. Корпус и запросы не изменены; положение относится к строке
произведения, а ID отчёта — к действительно найденному изданию.

Ручной smoke-test 2026-10-27 прочитал публичный указатель Толстого и сохранил его
во временной SQLite: 550 групп произведений, продолжение после первых 40,
17 записей изданий/томов «Анны Карениной», выбранный ID 766005. Временная база
удалена; карточки всех книг и файлы не скачивались. Эти числа описывают ответ
источника на момент проверки, а не фиксированный каталог.
