# Общее сопоставление запросов с каталогом

Поиск использует один детерминированный лексический механизм, а не правила для
отдельных ошибочных строк. Набор известных имён остаётся стартовой подсказкой,
но новый кандидат может прийти из любого ответа Flibusta и локального словаря
уже наблюдавшихся публичных имён. Новые авторы не добавляются в код для каждого
случая. AI, сторонний поисковый сервис или новая БД не требуются.

## Оценка кандидатов

`app/services/fuzzy_query.py` нормализует регистр, е/ё и порядок частей имени.
Расстояние optimal string alignment учитывает вставку, пропуск, замену буквы и
соседнюю перестановку. Сравниваются все части запроса; допустимость зависит от
длины и доли совпадения, а не от ограничения «одна ошибка в одном слове».
Короткие слова требуют сильного совпадения. Инициалы считаются совпадением одной
буквы, а не доказательством всего имени; запрос только из инициалов не угадывается.
Отсутствующее отчество допускается, разные полные подписи остаются различимыми.

Кандидаты предварительно отбираются по биграммам. Подробно оцениваются максимум
64 имени из ограниченного пула. Для многословного имени каждая часть должна
иметь сходство минимум 0.63, суммарное — 0.72. Если ближайшие варианты отличаются
менее чем на 0.07, предлагается уточнение (до трёх кандидатов). Коррекция имени
требует подтверждения: никакие книги или ID не выводятся на основании догадки.
Кавычки сохраняют буквальный поиск названия. Те же подсказки работают через
обычное сообщение и `/author`/кнопку поиска автора.

Эти пороги — правила принятия решения, не измеренные проценты точности.
Слишком сильное искажение, неполные данные или неоднозначность не дают права
объявить произвольного автора правильным. Механизм не вводит семантические
рекомендации и не обещает понимание любого свободного описания.

## Получение новых имён

Проба авторов использует исходный запрос, короткие подстроки его слов и оставшиеся
ограниченные варианты. Достаточно близкий кандидат останавливает дальнейшие пробы.
Уже полученные кандидаты сохраняются, даже если необязательная проба прерывается
по своему прежнему бюджету времени. Общий deadline поиска и максимум 4 запросов
авторов на один поиск сохранены; число книжных запросов не увеличено.

`CachedFlibustaClient` пополняет словарь только публичными именами из ответов
поиска книг/авторов, карточек и авторских указателей. Текст пользовательских
сообщений в этот словарь не включается. Словарь хранится в существующем SQLite
кэше: `author-name-lexicon:v1`, тип `author_lexicon`, TTL 30 дней. Максимум 2048
имён по 120 символов, актуальность поддерживается порядком наблюдения. Регистр,
е/ё и перестановка частей одной подписи не создают лишних вариантов выбора.

Записи сгруппированы не чаще раза в 60 секунд и при закрытии клиента, без нового
фонового процесса. Дополнительное чтение/запись имеет бюджет 0.1 секунды и не
блокирует результат каталога при сбое. Неудачное чтение не перезаписывает старый
словарь пустым. Это небольшой словарь увиденных имён, не зеркало всей Flibusta.

## Защита от мусорной выдачи

Раньше совпадения половины слов хватало: фамилия терялась, а результаты по
«Федр» становились ответом на весь запрос. Теперь каждое значимое слово должно
поддерживаться метаданными конкретного названия/автора; совпадение только имени
или другой половины запроса не принимается. Проверяются реальные подписи изданий,
поэтому номер тома не теряется после объединения в произведение. Точные длинные
названия не ограничиваются бюджетом нечёткого сравнения.

HTML-подсветка поиска также могла создавать искусственные пробелы:
`Ка<strong>федр</strong>а` превращалось в «Ка федр а». Текст ссылок теперь сохраняет
исходные пробелы вместо добавления пробела на каждой HTML-границе. Кэши книжного,
авторского и комбинированного поиска используют ключи `text-v2`, чтобы старые
искажённые строки не переживали исправление. Личные данные и другие кэши не
очищаются. Бот просит уточнить запрос, когда уверенного результата нет.

## Проверка

`tests/test_fuzzy_resolution.py` проверяет генерируемые повреждения имён, которых
нет в стартовом наборе, разные порядки слов, инициалы, неоднозначность, похожие
фамилии, полный контекст названия/автора, длинные названия, HTML-подсветку,
холодные пробы источника, сохранение словаря после перезапуска и его границы.
Также проверяется работа подтверждения через обычный и явный поиск автора.
Все unit-тесты используют моки; настоящий сетевой доступ и файлы книг не нужны.

Ручная проверка 2026-10-27 во временной SQLite: «Джонатам Франзеи» предложил
«Джонатан Франзен», «Кадзу Исигруо» — «Кадзуо Исигуро». В обоих случаях кандидат
получен из живой Flibusta за две пробы авторов, без добавления имени в код;
посторонние книги не выданы. Файлы не скачивались, временная база удалена.

Команды: `make check`, `make test-search`, `make test-kindle`,
`make search-quality`, `make search-benchmark`.
